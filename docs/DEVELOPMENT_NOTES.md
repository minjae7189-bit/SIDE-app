## 2. 동작 정책

- **기어**: P만 정차. R/N/D와 "알 수 없음"(연결 전, 연결 실패)은 주행으로 봅니다. N은 신호 대기일 수도 있지만 차가 움직일 수 있어 주행으로 처리합니다.
- **주행 화면**: 질문 텍스트·카드 없이 상태 문구와 큰 버튼 하나만 둡니다. 애니메이션과 화면 전환 효과는 없앴습니다(전환 페이드 동안 카드가 주행 중에 보이고 눌릴 수 있었음).
- **음성 진행**: 질문 → 8초 대기(아이가 부모에게 답하는 시간) → 직업 이야기 → 1.5초 쉼 → 다음 카드. 기어가 바뀌어도 대화는 이어지고 화면만 바뀝니다.
- **화면 이탈**: 다른 앱이 화면을 가리면(onStop) 일시정지, 돌아오면 "이어서 듣기". Pleos 멀티윈도우에서는 HOME/BACK 키만으로는 화면이 가려지지 않아 계속 진행됩니다.
- **오류**: 음성 엔진이 응답하지 않으면 10초 + 글자당 0.3초 뒤 일시정지하고 화면에 "음성을 재생하지 못했어요"를 표시합니다.

## 3. Pleos SDK에서 알아낸 것

공식 문서 일부가 JS 렌더링이라 읽히지 않아, SDK AAR을 `javap`로 분석하고 에뮬레이터 로그로 확인했습니다.

- **Maven 저장소**: `https://nexus-playground.pleos.ai/repository/maven-releases/`
  - `ai.pleos.playground:Vehicle:2.3.2` (vehicle 서비스 2.3.13 이상 필요, 에뮬레이터 2.3.22)
  - `ai.pleos.playground:TextToSpeech:3.3.1` (caas 4.1.29 이상 필요, 에뮬레이터 4.2.10)
- **권한**: `pleos.car.permission.CAR_DRIVE`, `pleos.car.permission.TTS_SERVICE` — 에뮬레이터에서 둘 다 `protectionLevel:normal` 확인. 런타임 요청 불필요.
- **TTS 로케일**: `Locale.KOREAN`("ko")은 온디바이스 엔진이 `unsupported locale: ko-`로 거부합니다. `Locale.KOREA`(ko_KR)를 써야 합니다.
- **TTS 모드**: SERVER/HYBRID는 Pleos Playground 프로젝트의 Client ID/Secret으로 `registerApp()`이 필요합니다(없으면 caas 로그에 `Client credentials missing`). 그래서 기본값은 ON_DEVICE.
- **TTS 초기화 순서**: `addEventListener()`를 `initialize()`보다 먼저 부르면 SDK 내부 `lateinit` 크래시.
- **TTS 이벤트**: 발화 ID가 없습니다. 새 `speak()`마다 `onStop → onReady → onStart → onDone` 순서로 오고, 중단된 발화에는 `onDone` 대신 `onStop`이 옵니다. 그래서 새 발화의 `onStart` 이후에 온 `onDone`만 완료로 인정합니다.
- **TTS stop/release**: `stop()`은 SDK 안에서 비동기로 처리됩니다. 직후에 `release()`하면 늦게 실행된 stop이 서비스를 다시 바인딩할 수 있어 release를 500ms 늦춥니다.
- **기어 API**: `Vehicle.getGear().registerGearSelection()`은 등록할 때 현재 값을 리스너로 바로 보내 줍니다. `getCurrentGearSelectionState()`를 따로 부르면 오래된 값이 덮어쓸 경로가 늘어 부르지 않습니다. Gear API는 AOSP `GEAR_SELECTION` 속성을 권장하며 deprecated 상태입니다(인터페이스 뒤에 두어 교체 가능).
- **Vehicle 서비스 단절**: SDK가 앱에 알리지 않고, 재연결 때 현재 값을 다시 읽지 않습니다.
- **에뮬레이터 가상 콘솔**: 에뮬레이터 안 8088 포트의 HTTP API로 기어를 바꿀 수 있습니다(`scripts/gear.sh`). 브라우저 세션 하트비트(`POST /browser/session`)가 있어야 입력을 받습니다. 공식 API가 아니라 버전이 바뀌면 동작하지 않을 수 있습니다.
- **에뮬레이터에는 안드로이드 기본 TTS 엔진이 없습니다.** 대체 엔진 경로는 실기기에서만 의미가 있습니다.

## 4. 코드 검토 기록

구현 후 관점이 다른 검토 에이전트 2개(적대적 반박, 독립 리뷰)로 3차례 검토하고, 지적마다 SDK 바이트코드와 에뮬레이터 실측으로 재검증해 반영했습니다.

**반영한 것**
- 음성 엔진 무응답 시 무한 대기 → 문장 길이 비례 시간 제한
- 기어 정보 실패 시 마지막 값(P)이 남아 주행 중 카드 노출 가능 → "알 수 없음"으로 복귀
- 중단된 발화의 늦은 완료 신호가 새 발화를 끝내는 경합 → `onStart` 이후 완료만 인정
- 대체 TTS 엔진이 Android 11+ 패키지 가시성 때문에 엔진을 못 찾음 → 매니페스트 `<queries>` 추가
- 대체 엔진 초기화 실패 뒤 영구 대기 → 실패 상태 기억 후 즉시 오류
- 주행 화면 펄스 애니메이션, 화면 전환 페이드 제거
- 마무리 인사 중 "처음부터 다시" 무반응, 마무리 실패 시 완료가 일시정지로 바뀌는 문제
- 디버그 시뮬 기어가 실제 기어 복구 뒤에도 우선하는 문제
- release 직전 stop 경합으로 인한 서비스 재바인딩 가능성
- README에 환경변수 자격증명 경고, JDK 17 요구사항

**기각한 것**
- "`onStop`을 받으면 완료로 처리하라" — 새 `speak()`마다 맨 앞에 `onStop`이 오므로 모든 발화가 즉시 끝나 버림(로그 확인)
- "normal 권한인지 미검증" — 에뮬레이터 `pm list permissions -f`로 확인함

## 7. 음성인식(STT) 연동 — 2026-11-14

질문을 읽은 뒤 "답을 듣는" 단계에서 Pleos SpeechToText SDK(`ai.pleos.playground:SpeechToText:3.3.1`)로 아이의 답을 듣습니다. 공모전 개발 가이드의 "음성 입출력 — SpeechToText SDK"가 이것입니다.

**동작**
- 질문 TTS가 끝나고 0.3초 뒤 마이크를 켭니다. 말을 마치면(확정 결과) 바로 직업 이야기로 넘어가고, 알아들은 말은 정차 화면에 표시하고 카드별로 저장합니다(관심사 키워드 추출에 쓸 예정).
- 8초 안에 말이 없으면 넘어갑니다. 말하는 중이면 최대 6초 더 기다리고, 그래도 확정되지 않으면 마지막 중간 결과를 씁니다.
- 일시적인 인식 오류면 잠깐 쉬고 다시 듣습니다. 엔진을 쓸 수 없으면 시간만 기다리고 "음성인식을 쓸 수 없어 기다려요"를 표시합니다.
- 듣기는 자동으로 시작합니다(버튼을 눌러야 듣는 방식은 쓰지 않기로 결정). 그래서 TV·라디오·어른 대화도 답으로 기록될 수 있습니다.
- 앱 코드는 아이 발화 원문을 디버그 빌드에서만 로그에 남깁니다. 다만 **Pleos STT SDK 자체가 release 빌드에서도 인식 결과를 logcat(`SttCallback` 태그)에 남깁니다**(실측). 막으려면 R8 난독화를 켜고 SDK 로그 함수를 제거하는 규칙이 필요합니다(미적용).

**SDK에서 알아낸 것**
- 권한은 `pleos.car.permission.STT_SERVICE`(normal) 하나입니다. 실제 녹음은 Pleos 음성 서비스(caas)가 하며 caas가 `RECORD_AUDIO`를 갖고 있습니다. 자격증명 없이 ON_DEVICE 모드로 녹음·인식되는 것을 실측했습니다.
- `onStartedRecognition`/`onEndedRecognition`은 세션 시작·끝이 아니라 말소리 감지(EPD) 상태 변화 신호입니다. 말하다 잠깐 쉬어도 옵니다. 확정 결과는 별도 메시지로 `onUpdated(text, isFinal=true)`에 옵니다. 처음에 종료 신호로 세션을 끝내게 만들었다가 답이 잘리는 문제가 있어 고쳤습니다.
- 말이 없으면 엔진이 약 2초 만에 빈 확정 결과로 끝냅니다. 그래서 대기 시간 안에서 다시 듣습니다.
- 콜백에 세션 구분이 없어서, 새 요청의 `onReady` 이후에 온 결과만 받습니다(실측상 세션마다 `onReady`가 먼저 옴).
- 에뮬레이터 마이크는 `adb emu avd hostmicon`으로 Mac 마이크에 연결해야 합니다. Mac 스피커로 재생한 문장은 잘 인식되지 않아 정확도는 직접 말해서 확인해야 합니다.

**아직 확인하지 못한 것**
- 실제 말소리에 대한 인식 정확도, 차량 마이크·뒷자리 조건
- HYBRID(서버 인식)에서의 이벤트 순서와 지연
- 세션마다 `onReady`가 반드시 오는지(오지 않으면 그 세션 결과를 받지 못하고 시간 제한으로 넘어감)

## 8. 내비게이션 연동(가 볼 만한 곳 → 차량 내비) — 2026-11-15

"가 볼 만한 곳"(장소 추천, `places/`)의 길 안내를 Pleos NaviHelper SDK(`ai.pleos.playground:NaviHelper:3.0.5`)로 차량 내비게이션에 연결했습니다.

**동작**
- 추천 기준 위치: 차량 내비의 현재 위치를 가장 먼저 씁니다(화면에 "차량 위치 기준"). 없으면 기존처럼 안드로이드 위치 → 서울시청 순서입니다.
- 장소 카드의 "내비에 넣기": 안내 중인 경로가 없으면 목적지로 안내를 시작하고, 있으면 경유지로 넣습니다(2곳까지). 결과는 화면 위쪽 문구로 알립니다. 내비에 연결할 수 없으면 버튼이 "길 안내"로 바뀌고 지도 앱을 엽니다.
- 넣는 규칙(`navi/NaviRouter.kt`의 `decide`, 단위 테스트 있음)
  - 주행 중에는 넣지 않습니다(운전 중 경로 변경과 내비 화면 전환 방지).
  - 넣기 직전에 내비 상태를 새로 읽습니다. 목적지 이름이 비어 있어도 좌표·안내 상태(ROUTE_DRIVE)·경로 상태(ROUTE_GUIDING) 중 하나라도 있으면 경로가 있다고 봐서 운전자의 목적지를 덮어쓰지 않습니다.
  - 이미 목적지·경유지에 있는 곳(이름 또는 200m 안 좌표)은 넣지 않고, 15초 안에 같은 곳을 다시 누르면 무시합니다.
  - SDK가 요청별 성공을 알려 주지 않아 "넣을게요"로 안내하고, 요청 직후 내비 오류가 오면 문구로 알립니다.
- 위치·목적지·경유지 이름은 디버그 빌드에서만 로그에 남깁니다.
- 디버그 빌드에는 adb로 내비를 시험하는 명령이 있습니다(`navi/NaviDebugReceiver.kt`, adb shell 권한이 있어야 보낼 수 있음).

**에뮬레이터에서 확인한 NaviHelper 동작**
- 권한: `pleos.car.permission.NAVI_ROUTE`(읽기), `NAVI_ROUTE_SEARCH`(경로·경유지 요청), 둘 다 normal.
- 차량 현재 위치는 내비 자체 위치(37.4127, 127.0947, 성남시 수정구 시흥동)이고, `adb emu geo fix`로는 바뀌지 않습니다.
- `requestRoute`: 목적지 경로가 바로 잡히고 내비 앱이 앞으로 나옵니다(한국잡월드 12분·5.2km).
- `addWaypoint`: 경로가 있을 때만 됩니다. 경로가 없으면 `onError(CAUSE_SEARCH_ROUTE)`. FIRST·SECOND 두 곳까지 들어가고 경로를 다시 계산합니다.
- 리스너는 초기화 성공 뒤에 등록합니다.
- `RequestWaypointInfo`·`RouteInfo`의 `poiId`가 필수인데 NaviHelper에는 장소 검색 API가 없어 빈 값으로 보냅니다. 내비 서버가 장소 상세 조회를 거절(`pid - must not be empty`)하고, 한 번은 내비 앱에 "경로 탐색 오류 - Invalid Parameter" 대화상자가 떴습니다. 경로 자체는 정상으로 잡힙니다.
- SDK는 서비스 연결이 끊긴 동안의 요청을 쌓아 두었다가 다시 연결되면 보내는 것으로 보입니다(경로 취소 뒤 예전 경유지 추가가 다시 재생됨). 에뮬레이터 내비에 이전 시험 경로가 남으면 내비 앱에서 직접 "안내 종료"해야 합니다.

**아직 확인하지 못한 것**
- 실차에서 POI ID 없이 넣었을 때의 표시, 연결이 끊긴 동안 쌓인 요청이 나중에 실행되는 문제의 대책
- 내비 초기화가 실패하면 앱을 다시 켤 때까지 재시도하지 않습니다.
- FusedLocation SDK는 쓰지 않았습니다(NaviHelper가 차량 위치를 주므로). 기획서 표에는 FusedLocation이 있어 필요하면 추가합니다.
- 이전에 만든 "내장 7곳 추천 + 토크 뒤 음성 승낙으로 내비에 넣기" 버전은 "가 볼 만한 곳"과 겹쳐서 합치지 않고 로컬 브랜치 `backup/navihelper-fb4e8f6`에만 남겨 두었습니다.
