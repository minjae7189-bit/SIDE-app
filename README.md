# SIDE — Shared Ideas, Dreams & Exploration

> **나란히 앉아, 내일을 향해.** 가족이 나란히 앉아 가는 차 안을 아이의 진로를 함께 이야기하는 대화의 공간으로 바꾸는 차량용 앱

아이와 함께 탄 어른(부모·조부모·보호자)이 같은 길을 보며, 앱이 음성으로 건네는 질문에 답하고 이야기를 나눕니다.
주행 중에는 음성만 쓰고, 정차(P단) 중에만 화면 카드를 보여 줍니다. 이야기를 마치면 오늘 나온 관심사와 어울리는 가까운 박물관·과학관·체험처를 이유와 함께 권하고, 차량 내비에 바로 넣을 수 있습니다.

## 실행 방법

### APK로 바로 실행

1. Pleos Connect 에뮬레이터(v2.1.0)를 켭니다.
2. APK를 설치하고 실행합니다.

   ```bash
   adb install -r apk/SIDE_SIDE_release.apk
   adb shell am start -n app.side/.MainActivity
   ```

3. 에뮬레이터의 가상 콘솔에서 기어를 바꿔 봅니다. P단이면 카드 화면, R·N·D단이면 음성 위주 화면입니다.
   아래 스크립트로도 바꿀 수 있습니다(녹화할 때 편함).

   ```bash
   scripts/gear.sh D   # 주행 화면
   scripts/gear.sh P   # 카드 화면
   ```

   스크립트는 에뮬레이터 안의 가상 콘솔 HTTP API(포트 8088)를 `adb forward`로 호출합니다. 공식 API가 아니어서 에뮬레이터 버전이 바뀌면 동작하지 않을 수 있습니다.

### 소스에서 빌드

```bash
./gradlew assembleRelease          # app/build/outputs/apk/release/app-release.apk
./gradlew testDebugUnitTest        # 단위 테스트
```

## 테스트 환경 및 필요한 설정

- **개발 도구**: Android Studio, JDK 17, Kotlin 2.2, Jetpack Compose, AGP 8.11, Gradle 8.14.3(wrapper 포함)
- **SDK 수준**: minSdk 28 / targetSdk 35 / compileSdk 35
- **Pleos SDK**: `ai.pleos.playground:Vehicle:2.3.2`, `TextToSpeech:3.3.1`, `SpeechToText:3.3.1`, NaviHelper. 저장소는 `settings.gradle.kts`에 등록된 Pleos Playground Maven(`nexus-playground.pleos.ai`)에서 받습니다.
- **권한**: `pleos.car.permission.CAR_DRIVE`, `TTS_SERVICE`, `STT_SERVICE`, `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`(모두 매니페스트 선언만으로 충분). 안드로이드 위치 권한은 쓰지 않습니다(아래 "구현 메모" 참고).
- **따로 넣을 값 없음**: 음성 합성은 ON_DEVICE 모드라 앱 등록이나 자격증명 없이 동작합니다. 제출 APK도 자격증명 없이 빌드했습니다.
- **마이크**: 음성 대답(STT)은 에뮬레이터가 PC 마이크를 씁니다. 에뮬레이터 설정에서 마이크 입력을 켜 주세요.
- **내비**: "함께 가 볼 곳"의 기준 위치는 차량 내비(NaviHelper)의 현재 위치입니다. 받지 못하면 서울시청 기준으로 추천하고 화면에 그렇게 밝힙니다.

## 1차 데모 범위 (2026-11-15 마감)

앱은 네 단계로 이어집니다: **① 이야기 → ② 진로 검사 → ③ 직업 탐험 → ④ 함께 가 볼 곳**. 홈 하단 타일과 왼쪽 메뉴 번호가 같습니다.

- **기어 상태에 따른 화면 전환**: Vehicle SDK로 기어를 받아 P단이면 카드 화면, 그 밖의 기어면 음성 위주 최소 화면. 기어를 바꿔도 대화는 끊기지 않고 화면만 바뀜
- **① 음성 이야기**: TextToSpeech로 카드를 읽고(질문 → 8초 기다림 → 이야기 → 다음 카드), SpeechToText로 아이의 대답을 알아들음
  - 이야기 카드 8장: 답하기 쉬운 질문부터 함께 탄 어른의 차례, 창밖 관찰까지
  - 밸런스 게임 6장: 취미·적성을 두 갈래로 고르고, 고른 쪽과 어울리는 홀랜드 유형·직업을 들려줌. "첫 번째", "뒤에 거"나 보기 속 낱말로 말해서 고름
  - 직업 퀴즈 5장: 비슷한 직업 셋 중 정답 맞히기
  - 가족 MBTI 5장: 네 축을 가족 모두 하나씩 고르는 게임으로 묻고, 서로 다를 때 조심할 점을 들려줌. 정차 중 "가족 MBTI" 화면에서 축마다 "조심하세요 / 이렇게 해 보세요" 팁. MBTI는 서로를 이해하는 놀이로만 쓰고 진로·성격 판정에는 쓰지 않음
- **② 진로 검사(데모 문항)**: 초등 저학년·초등 고학년·중학생·고등학생 네 학교급. 화면으로 답하거나, 음성으로 문항을 듣고 번호나 응답 문구로 대답(주행 중에도 음성으로 이어짐)
- **③ 직업 탐험**: 분야를 고르면 직업과 하는 일, 관련된 가까운 장소를 보여 주고 바로 내비에 넣음
- **④ 함께 가 볼 곳**: 오늘 나온 관심사로 가까운 문화시설 세 곳을 이유와 함께 추천, 차량 내비 목적지·경유지로 넣기
- **성장 기록**: 마친 이야기 카드(질문과 알아들은 대답), 진로 검사 결과, 내비에 넣은 장소를 날짜별로 기기 안에만 저장
- 다른 앱이 화면을 차지하면(액티비티 onStop) 진행 중인 토크를 일시정지하고, 돌아오면 "이어서 듣기"로 다시 시작

| 기어 | 화면 | 조작 |
| --- | --- | --- |
| P | 왼쪽 메뉴 + 홈·이야기·진로 검사·직업 탐험·함께 가 볼 곳·성장 기록 | 화면 터치와 음성 |
| R / N / D | 음성 상태 표시(질문 n/5, 듣는 중 등) | 큰 시작/멈춤 버튼 하나, 음성 |
| 알 수 없음(연결 전·연결 실패) | 주행 화면과 같음(안전한 쪽으로 처리) | 〃 |

N단은 신호 대기일 수도 있지만 차가 움직일 수 있어서 주행으로 봅니다.

PT 버전(12/3)에서 할 일: LLM 다음 질문 생성, 진로 여정 기록 고도화.

## 음성 합성 모드와 자격증명(선택)

- 기본값은 **ON_DEVICE** 모드라서 앱 등록 없이 동작합니다.
- 서버 합성(HYBRID)을 쓰려면 Pleos Playground 프로젝트에서 발급받은 값을 `local.properties`에 넣습니다. 그러면 HYBRID 모드로 `registerApp()`을 호출합니다.

  ```properties
  PLEOS_CLIENT_ID=...
  PLEOS_CLIENT_SECRET=...
  ```

  같은 이름의 환경변수(`PLEOS_CLIENT_ID`, `PLEOS_CLIENT_SECRET`)로도 넣을 수 있습니다.
  `local.properties`는 git에 올라가지 않지만, 값이 APK 안의 `BuildConfig`에 평문으로 들어갑니다. 제출용 APK(`apk/`)는 `local.properties`와 환경변수 **둘 다** 비운 상태로 빌드하세요.
- Pleos TTS를 초기화할 수 없으면 안드로이드 기본 TTS로 바뀝니다. 다만 Pleos 에뮬레이터에는 기본 TTS 엔진이 설치돼 있지 않아서, 이 경우 화면에 "음성을 재생하지 못했어요"가 표시됩니다.
- 음성 엔진이 응답하지 않으면 문장 길이에 비례한 시간(10초 + 글자당 0.3초)이 지난 뒤 일시정지하고 오류를 표시합니다.

## 디버그용 기어 시뮬레이터

Vehicle SDK가 실패를 알려 온 경우(권한 없음, 리스너 실패 등)에는 디버그 빌드 화면 오른쪽 위에 `기어 시뮬 P / D / 실제` 막대가 나타납니다. 릴리스 빌드에는 나오지 않습니다. 서비스 바인딩이 조용히 실패하는 환경에서는 SDK가 실패를 알려 주지 않아 막대가 뜨지 않고, 화면은 안전하게 주행 화면으로 남습니다.

## 진로 검사(데모)

정차 중에 흥미·적성·가치관을 짧게 알아보는 진로 검사를 할 수 있습니다. **이 저장소의 문항은 화면 흐름과 채점 방식을 보여 주기 위한 데모용 예시(18문항)이며, 실제 서비스에서는 검증된 진로검사 문항으로 바꿉니다.**

- **학교급**: 초등 저학년(1~3학년)·초등 고학년(4~6학년)·중학생·고등학생. 학교급마다 문항, 응답 문구("전혀 아니에요 … 아주 그래요"), 과목 보기가 다릅니다.
- **음성으로 하기**: 문항을 읽고 8초 동안 대답을 듣습니다. "3번", 응답 문구, "아주 그래요" 같은 정도어로 대답하면 알아들은 답을 다시 읽어 준 뒤 넣고, 애매하면 다시 묻습니다. 주행 중에도 음성으로 이어집니다.
- **흐름**: 소개 → 기본 정보(학교급·학년·성별·지역, 잘하는 과목 1~3순위) → 문항 → 결과
- **채점**: 홀랜드 RIASEC 방식. 문항 점수를 하위요인에 연결된 유형에 더하고 총점 상위 두 유형으로 코드를 정합니다. 동점이면 총점 → 5점 이상 문항 수 → R > I > A > S > E > C 순서.
- **결과**: 유형 코드와 예시 직업, RIASEC 육각형, 영역별 막대와 문장, 일관성·변별성
- **저장**: 응답은 기기에만 저장되어 기어를 바꾸거나 앱을 다시 켜도 이어서 할 수 있습니다. 주행 중에는 검사 화면이 보이지 않습니다(음성은 이어짐).
- **자료**: `app/src/main/assets/career_test_demo.json`

채점 확인: `./gradlew testDebugUnitTest`

## 함께 가 볼 곳(장소 추천)

이야기를 나눈 뒤, 현재 위치에서 가까우면서 오늘 이야기와 어울리는 문화시설을 이유와 함께 권합니다.

- **관심 근거**: 정차 화면에서 고른 "오늘 나온 관심사"(가중치 3), 음성인식으로 알아들은 아이의 답 속 낱말(2, 예: "우주"→과학·기술, "축구"→몸으로 놀기), 진로 검사 흥미 최고점 하위요인(2)·두 번째(1), 오늘 이야기까지 들은 카드(1)를 10가지 주제(과학·기술, 자연·생태, 역사·문화, 미술·디자인, 음악·공연, 책·글, 만들기·체험, 몸으로 놀기, 모험·놀이, 사람·나눔)로 모읍니다. 아이의 답은 기기 안에서만 쓰고 저장하지 않습니다(앱을 다시 켜면 사라짐).
- **고르는 방법**: 30km 안(모자라면 80km)에서 `관심 점수 × 종류 가중치 ÷ (1 + 거리/8km)`가 높은 순으로 세 곳. 주제·종류가 겹치지 않게 고르고, 성인 대상 유료 강좌가 많은 체험 클래스는 낮게(0.4) 보고 한 곳까지만 넣습니다.
- **화면**: 왼쪽 메뉴와 홈의 ④ "함께 가 볼 곳", 또는 이야기를 마치면 이야기 화면의 "함께 가 볼 곳" 버튼. 장소마다 소개, 운영 시간·휴관·어린이 관람료(있는 곳만), "왜 여기?"(근거 + 거리), "가서 이렇게"(주제별 대화 제안), "내비에 넣기" 버튼(차량 내비 목적지·경유지, 주행 중에는 넣지 않음)을 보여 줍니다.
- **쉬는 날 빼기**: 오늘이 매주 쉬는 요일인 곳(예: 매주 월요일 휴관)은 추천하지 않습니다. 공휴일·명절 휴관은 판단하지 못합니다.
- **음성**: 카드를 다 마치면 마무리 인사 뒤에 가장 잘 맞는 한 곳을 소리로 권합니다("여기서 12킬로미터쯤… 차를 세우면 화면에서 이유와 길 안내를 볼 수 있어요"). 주행 중에는 화면이 바뀌지 않습니다.
- **위치**: 차량 내비(NaviHelper)의 현재 위치를 씁니다. 받지 못하면 서울시청 기준이라고 화면에 밝히고, 음성 안내에서는 거리를 말하지 않습니다.
- **자료**: `scripts/build_places.py`가 아래 자료를 `app/src/main/assets/places.json`(약 9,950곳, 1.6MB)으로 만듭니다. 원본 자료는 저장소에 넣지 않았습니다.
  - 전국박물관미술관정보표준데이터: 박물관·미술관 1,023곳의 정확한 좌표, 관람 시간, 휴관 정보, 어린이 관람료, 소개. 총람과 같은 곳(이름이 같거나 3km 안에서 이름이 겹치는 곳)은 이것으로 바꿈
  - 전국공공시설개방정보표준데이터: 가족이 들를 만한 137곳(전시실, 캠핑장, 상시 개방 운동장). 회의실·강의실 같은 대관 공간은 뺌
  - 2025 전국 문화기반시설 총람(박물관·미술관·문학관·도서관·공연장·생활문화센터·문화원·문화의집)
  - 한국문화정보원 전국 문화 여가 활동 시설(액티비티): 아이와 갈 만한 종류만(클라이밍, 볼링장, 방탈출, VR, 레일바이크 등)
  - 한국문화정보원 전국 문화 여가 활동 시설(클래스): 미술·음악·공예·요리 등 체험 종류만
  - 총람에 없는 국립과학관 다섯 곳은 스크립트에 직접 넣음
  - 분류가 잘못된 노래연습장 등은 이름으로, 총람에 "(휴관)"으로 표시된 곳은 빼고 넣음

  ```bash
  python3 scripts/build_places.py "<자료 폴더>" .
  ```

- **확인할 것**
  - 박물관·미술관 표준데이터와 공공시설 개방 자료에 없는 총람 시설(도서관·공연장·문화원 등)과 클래스는 좌표가 없어, 액티비티 자료의 좌표로 같은 도로명 → 읍면동 → 시군구의 평균 위치를 대신 씁니다. 표본 확인에서 실제 위치와 0.5~1.5km 차이였고, 화면에는 "약 ○km"로 표시합니다.
  - 액티비티·클래스 자료는 2022년 기준이라 문을 닫은 곳이 있을 수 있습니다.
  - 운영 시간은 평일 기준만 보여 줍니다(주말·공휴일 시간은 자료에 있지만 아직 쓰지 않음).

추천 확인: `./gradlew testDebugUnitTest` (거리 계산, 관심사별 선택, 체험 클래스 제한, 아이가 말한 낱말, 쉬는 날 빼기, 근거 문장)

## 로고와 그림

로고, 앱 아이콘, 홈 그림, 직업 분야 아이콘은 모두 벡터 그림입니다. `scripts/gen_assets.py`가 같은 도형 목록으로 공유용 SVG(`design/assets/`)와 앱용 벡터(`app/src/main/res/drawable/`)를 함께 만듭니다. 색이나 모양을 바꿀 때는 스크립트를 고친 뒤 다시 실행하세요(fonttools 필요).

```bash
python3 scripts/gen_assets.py .
```

| 파일 | 내용 | 쓰이는 곳 |
| --- | --- | --- |
| `side_logo` | 표식 + 고운바탕 Bold "SIDE" | 왼쪽 메뉴 맨 위 |
| `side_logo_slogan` / `side_logo_stacked` | 표식 + SIDE + 슬로건 "side by side, toward tomorrow"(가로형·세로형). 슬로건은 Instrument Serif Italic 윤곽을 도형으로 넣어 앱에 글꼴을 더하지 않음 | 발표 자료·홍보물, 필요하면 시작 화면 |
| `side_store_icon` (SVG만) | 512 크기 아이콘에 이름과 슬로건 | 앱 스토어·홍보용 |
| `side_logo_mark` | 지평선 위로 떠오르는 해와 나란히 뻗은 두 줄의 길 | 앱 아이콘, 단독 표식 |
| `ic_launcher_*` | 적응형 앱 아이콘(배경·전경·단색) | 런처 |
| `side_home_hero` | 새벽 길 위의 차, 뒷유리 너머 나란히 앉은 어른과 아이 | 홈 오른쪽 |
| `side_field_*` | 우주·항공, IT·AI, 환경·에너지, 보건·의료, 콘텐츠·미디어, 사회·공공 선 아이콘 | 직업 탐험 칸 |

그림 자리는 이름으로 찾기 때문에, 같은 이름의 PNG를 `res/drawable-nodpi/`에 넣고 같은 이름의 벡터 XML을 지우면 코드 수정 없이 다른 그림으로 바꿀 수 있습니다.

## 구현 메모 (개발 확인 사항)

- **위치 권한을 쓰지 않는 이유**: 매니페스트에 `ACCESS_COARSE_LOCATION`·`ACCESS_FINE_LOCATION`을 선언하면, 기어를 D로 바꿨을 때 Pleos 홈 화면이 앱 패널 전체를 "주행 중에는 사용할 수 없습니다"로 덮었습니다(에뮬레이터 v2.1.0 실측, `distractionOptimized`와 무관). 그래서 위치는 차량 내비(NaviHelper)에서 받습니다.
- **주행 중 화면 제한**: 액티비티에 `distractionOptimized` 메타데이터를 선언했습니다. 에뮬레이터에서 D단으로 바꿔도 시스템 차단 화면이 뜨지 않는 것을 확인했습니다. AAOS는 user 빌드에서 허용된 설치 출처의 앱만 `distractionOptimized`를 인정할 수 있어서, 실차에서 사이드로드한 APK가 어떻게 처리되는지와 심사 기준(Activity Distraction 가이드 범위)은 따로 확인해야 합니다. 주행 화면은 애니메이션 없이 상태 문구와 버튼 하나만 두고, 기어가 바뀌면 화면을 전환 효과 없이 즉시 바꿉니다.
- **권한**: `pleos.car.permission.CAR_DRIVE`, `pleos.car.permission.TTS_SERVICE`. 둘 다 normal 권한이라 매니페스트 선언만으로 충분합니다.
- **SDK 주의점**
  - `TextToSpeech.addEventListener()`를 `initialize()`보다 먼저 호출하면 SDK 안에서 `lateinit` 크래시가 납니다. 앱은 초기화 성공 콜백에서 등록합니다.
  - TTS 이벤트에는 발화 ID가 없습니다. (ON_DEVICE 모드에서 확인. HYBRID 서버 합성 경로에서도 `onStart`가 오는지는 자격증명이 없어 확인하지 못했습니다.) 중단된 발화의 늦은 `onDone`이 새 발화를 끝내지 않도록, 새 발화의 `onStart` 이후에 온 `onDone`만 인정합니다. `stop()`된 발화에는 `onDone` 대신 `onStop`이 오는 것을 로그로 확인했습니다.
  - `registerGearSelection()`은 등록할 때 현재 기어를 리스너로 바로 보내 줍니다. 그래서 `getCurrentGearSelectionState()`를 따로 부르지 않습니다(오래된 값이 덮어쓸 경로를 줄이기 위함. SDK 내부의 초기값 읽기와 변경 이벤트 사이 경합은 남아 있어 시작 직후 기어 변경이 겹치면 드물게 틀릴 수 있음).
  - 온디바이스 TTS는 `Locale.KOREAN`("ko")을 거부합니다(`unsupported locale: ko-`). `Locale.KOREA`(ko_KR)를 써야 합니다.
  - `Gear` API는 AOSP `GEAR_SELECTION` 속성을 쓰라는 이유로 deprecated 상태입니다. `DriveStateSource` 인터페이스 뒤에 두어서 `CarPropertyManager` 구현으로 바꿀 수 있습니다.
- Vehicle 서비스가 끊겼다 다시 연결될 때 SDK가 앱에 알리지 않아서, 그 사이의 기어 변경은 다음 변경 이벤트가 올 때까지 반영되지 않을 수 있습니다(미해결).
- 오디오 포커스는 Pleos TTS 서비스에 맡기고 있습니다. 내비 안내 음성과 겹칠 때의 동작은 아직 확인하지 않았습니다.
- 진로 카드는 1차 데모용 샘플입니다. 실제 서비스에서는 검증된 진로 토크 콘텐츠를 음성 콘텐츠로 바꿔 넣습니다.
